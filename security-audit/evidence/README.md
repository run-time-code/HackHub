# Evidence traceability index (EVID-01)

This directory holds the audit's raw artifacts. Read it with three rules:

1. **Raw artifacts are authoritative.** `summary-*.txt` files are presentation
   aids generated by `make_tool_evidence.py`; each one starts with a
   `# GENERATED SUMMARY` header. If a summary and its raw artifact disagree,
   the raw artifact wins.
2. **Every claim must point here.** A report claim that cannot be traced to a
   file in this table is unsupported and must be removed or re-run.
3. **Nothing here contains live credentials.** Values were redacted for
   `SEC-02`; secrets are supplied through environment variables at runtime.
   Redaction changes are marked in the affected files.

## Rebuilt manual suite

`security-audit/manual_tests.py` replaces the 43-check suite:

- every mutation obtains a CSRF token from its own session;
- checks assert exact status codes plus a response-body invariant;
- an injection or enumeration check that returns 403 (missing CSRF) is a
  `FAIL`, not a `PASS`;
- two separate user sessions are used for IDOR/BOLA checks;
- secrets come from the environment (`AUDIT_TEST_PASSWORD`,
  `AUDIT_ACCESS_TOKEN_SECRET`, `AUDIT_*_EMAIL/PASSWORD`) and are never written
  to evidence; details are redacted before output.

Results are **pending**: a live API, MongoDB and a seeded database were not
available in this environment (`mongod` not installed, no `apps/api/.env`).
Run it and write new evidence with:

```bash
AUDIT_TEST_PASSWORD='<throwaway>' \
AUDIT_ACCESS_TOKEN_SECRET='<test-only signing secret>' \
security-audit/tools/venv/bin/python security-audit/manual_tests.py --write
```

Until that run exists, no manual-suite claim beyond the historical baseline is
supported.
